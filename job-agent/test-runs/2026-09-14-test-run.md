## Step 5: Resume tailoring (proof of concept)

Tailored one resume against the best-documented match — **EY, Product Owner, Bengaluru** — using `bespoke-jd`'s methodology (gap analysis, heavy restructure, JD-vocabulary reframing) against `resume-base.md`. Output: `tailored-resumes/EY/EY-ProductOwner-2026-09-14.docx` + ATS `.txt`.

**Gap:** Because the full JD wasn't fetchable, the tailoring is based on the WebSearch summary only (years of experience, role focus) rather than the complete requirements list, nice-to-haves, and exact phrasing a full JD would give. Quality is reasonable but not what `bespoke-jd` is designed to produce with a complete JD.

**Gap:** `bespoke-jd`'s default output bundle is 5 files (resume .docx/.pdf/.txt + cover letter .docx/.pdf) saved to an OS-aware Desktop path. This test only produced resume .docx + .txt, saved into the repo instead, because:
- **PDF generation failed.** `soffice`/LibreOffice is installed but cannot load any file, even a trivial one — `Error: source file could not be loaded` regardless of input. This looks like a sandbox restriction in this environment, not a missing dependency. Per the skill's own fallback rule, PDF should be skipped with a warning (done here) rather than blocking the run.
- **Cover letter was skipped** for this test run to keep the proof-of-concept scoped — the daily agent should generate it too per the skill's default bundle.
- **`python-docx` was not pre-installed** — had to `pip install python-docx` manually mid-run. This works (network egress allows PyPI), but it's a one-off install that may not survive a container rebuild between scheduled runs.

## Summary of gaps found (see also the message in chat)

1. Microsoft, KPMG, PwC career portals aren't search-indexed — need a different discovery method for those three.
2. WebFetch to career-site domains is blocked by org egress policy — can't pull full JD text or verify a posting is still live.
3. LibreOffice can't load any file in this environment — PDF output isn't currently possible; resumes will be DOCX + ATS-TXT only until this is fixed.
4. `python-docx` isn't part of the base image — needs a one-time setup step so it's available on every scheduled run, not just this manual test.
5. Cover letter generation wasn't exercised in this test — should be added to the daily routine's output bundle.
